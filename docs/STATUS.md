## 1. V0.2 平台

**是什么**：站型设计器 + 七类管控措施 + 管控时间轴 + 疏散路由插件 SDK + 固定种子配对实验 +
证据报告 + 导出/导入复跑。浏览器里从模板开始，30 分钟内能跑完一个 2×3 配对实验。

**现在在哪**（`docs/product/RELEASE_REVIEW.md`，评审日 2026-07-16）：

| 轴 | 状态 |
|---|---|
| 工程就绪度 | **pass 5/5** — R0～R4 全范围、全量回归、架构契约、站型 smoke、浏览器黄金路径全通过 |
| 仿真可信度 | conditional — 教学/方法研究可用，生产不可用 |
| 产品价值 | **blocked** — 没有真实用户任务证据 |

**卡在哪**：两条门禁，都不是代码。

1. 5 次目标用户黄金任务，至少 4 次成功，模板实验中位时间 ≤ 30 分钟
2. 2 名独立参与者在不改核心包的前提下接入自己的路由算法，中位时间 ≤ 90 分钟

**下一步**：安排人。产品审计原话是"可以停止新增功能并转入真实用户验收"。
**学生本身就是目标受众之一——给学弟用这件事，就是缺的那个输入，不是发布之后的结果。**

**使用边界**（交付时必须一起给）：

- 仅限教学、方法研究和受控内部探索
- **不得用于真实运营调整、容量承诺、疏散认证或消防结论**
- "未校准"状态必须随每份报告传播
- 不得根据 3 个种子的单次结果判断算法优劣
- 进程隔离用于故障控制，不是安全沙箱；本地插件必须先审查

## 2. 云跑批服务

**是什么**：把"跑一次仿真"变成 HTTP 接口。提交一组参数，服务在云主机上跑，
产出可以直接 `pd.read_parquet` 的轨迹数据。使用者不需要装 Mesa/JuPedSim。

**现在在哪**（`docs/cloud/`，目标上线 2026-08-25）：

- 契约 `01-jobspec` / `02-outputs` 已冻结为 v0.1-frozen
- 本机真实 runner 四档 spike（25/50/100/200 agent）全部通过完整产物契约
- 本机 10×50 soak 通过，本机真实 HTTP E2E 通过
- 39 tests、Ruff/Pyright/锁文件/build 通过，systemd 单元与部署/故障脚本就绪

**卡在哪**：五项目标机验收（`docs/cloud/06-tasks.md` 末尾），脚本都已写好：

- [ ] ECS 复跑四档 spike
- [ ] Linux 实测 timeout/cancel 后无孤儿进程
- [ ] worker SIGKILL 后重启恢复 summary
- [ ] ECS 连续 10 个 50-agent job，检查磁盘/cgroup
- [ ] SSH-only 网络验收（**必须从 ECS 外部机器**确认 8000 不可达）

**开放给多人前必须先决策的两项**（超出原 single-user 设计假设，未登记在上表）：

1. **用户隔离**。当前 `GET /v1/jobs` 列出所有人的 job，任何持 token 的人能取消别人的
   running job、下载别人的产物。建议不做多租户，改用 label 前缀约定或每人独立部署实例。
2. **参数区间与实测区间不一致**。契约允许 `horizon_minutes ≤ 60`，实测只到 900 秒；
   worker 串行、job timeout 14400 秒 —— 一个合法请求能把队列堵最长 4 小时。
   开放前要么把上限降到 15，要么补一次 60 分钟 spike。

**可选范围**：catalog 目前只有 3 个站（小寨/钟楼/北大街）和 **1 个站型模板**。
开放前先确认这够不够用途。

## 3. alignment 标定

**是什么**：把仿真的行人速度/密度与真实行人轨迹数据对齐，让仿真结果能进研究结论。
共 9 步。

**现在在哪**：

| 步 | 内容 | 状态 |
|---|---|---|
| 1–4 | 工程化、数据注册、canonical 格式、观测侧指标 | pass |
| **5** | 仿真轨迹源完整性 | **Round 28 收口：软件结论完成，服务限制已登记** |
| **6** | 观测-仿真对比 | **数据阻塞** |
| 7–8 | 报告、交付隔离 | pass |
| 9 | 三方复核 | 持续 |

**Round 28 做了什么**（`alignment/docs/reviews/round_28_closing_review.md`）：
完成 Round25–27 证据线合并，复现并定性了基线 same-tick 失败，按固定 cohort 完成三次
针对性尝试，并将 `platform_boarding` 明确标记为 `synthetic_declared`。最终 2,404 个排程
需求完成 571 个，独立重算服务比例 23.752%；源守恒、零丢失、零 placement retry、零
liveness violation 通过，但 DEBT-2 仍超过 1% 重规划门槛，作为已知服务限制收口。

**卡在哪**：Step 6 需要观测匹配的几何和非代理的速度证据。
当前对照场景 `platform_boarding` 是一块 **82.3 × 17.6 m 的矩形，长宽取自荷兰埃因霍温
中央车站站台轨迹数据集的外接矩形**，里面的闸机、车门、通道位置全部是构造的。
**这一条不管再写多少轮代码都不会通过**，需要真实站台的观测数据。

**下一步**：不再安排 Round 29 工程搜索。只有补齐真实站台/车辆观测数据，或出现新的外部
可验证失败机制，才重新立项；Step 6 不在当前工程线内。
