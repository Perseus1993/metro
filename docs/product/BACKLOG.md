# 产品 Backlog

当前排序围绕“V0.2 管控措施与疏散算法实验平台”。分数使用：

`(2 × 用户影响 + 2 × 战略匹配 + 证据增益 + 紧迫度) / (工作量 + 风险)`

分值基于现有仓库证据和本轮产品方向，仍需教师、学生和算法研究者任务校正。P0 表示 V0.2 黄金路径阻断项，优先于纯分数。

## 当前上游风险观察（2026-08-01）

- **已定位并修复一项上游根因**：`paid_hall` / `exit_hall` 曾把多名旅客精确导向 `(55, 24)`，造成与 Unity 无关的同点汇聚。现在由上游为旅客生成确定性、可复跑的站厅目标分散点，并投影回可步行区；100 人样本中该目标的正常步行同点对由 19 降为 0。
- **新增根因修复**：疏散旅客过去必须先走到单一“垂直交通决策区”才选择设施；旧 100 人样本第 37 秒有 76 人形成连通密集团，其中 56 人仍未选择设施。现在按各层可步行连通分量和真实垂直设施连接关系生成疏散 Journey，并在可到达的设施入口完成物理选择；不会把当前位置伪装成已到达的决策区域。
- **当前默认演示**：Unity 使用 50 人、1 秒权威快照，50/50 于 253 秒清场；0～120 秒最大 0.75 米连通团为 3～5 人。100 人同修复样本 100/100 于 286 秒清场，但设施银行前仍会出现 71 人汇流，作为容量样本保留；300 人继续作为压力测试。
- **仍待处理**：局部高密队列仍可能由设施容量、共同路径段、路点吸附或局部避碰形成；300 人尚未用新目标分散逻辑完成同口径复验。时间步敏感性仍需重新建立，旧修复前 1 秒/2 秒结果不能直接作为新版本对比。
- **完成条件**：100/300 人都用同一版本路由与目标分散逻辑通过；报告首个高密时刻、设施/目标 ID、队列和服务证据；完成独立现场数据校准前，只能称研究/教学仿真，不能称安全预测或数字孪生。

## 接口分层规则

以下是四个独立产品边界，禁止出现统一 `AlgorithmPlugin`：

| 层 | 合同职责 | 输入 | 输出 | V0.2 状态 |
|---|---|---|---|---|
| 策略接口 | 在出口、楼梯、扶梯等候选设施中作选择 | 候选设施、可达性、队列、密度、旅客意图 | 设施 ID、得分、理由 | 复用/冻结边界，不开放 SDK |
| 疏散路由接口 | 在动态拓扑上生成全局路径 | 拓扑快照、关闭边、起终点、群组、时刻、种子 | 有序节点/边、成本、诊断 | V0.2 唯一插件 SDK |
| 运动模型接口 | 更新局部移动和避碰 | 位置、邻居、可行域、目标速度、时间步 | 下一状态、碰撞/约束诊断 | 后续重新设计；不得暴露 Mesa Agent |
| 实验优化接口 | 跨多次仿真生成和排序管控方案 | 参数空间、约束、目标、预算、评估回调 | 排名方案、试验历史、停止原因 | P2 |

## 启停规则

- V02-DEV-001 和 ADR-007 评审通过前，不开发插件 UI 或完整管控组件视觉。
- R0 必须先用“水马投放/移除 + 出口关闭/恢复”贯通合同、运行、回放和报告，再扩七类措施。
- R2 必须先用内置基线与示例插件贯通单个种子，再扩成多算法配对矩阵。
- 任何插件失败、时间事件未应用或配对输入漂移都必须阻断研究结论并进入报告。
- 自动优化、云协作和新 3D 资产在 V0.2 P0 全部通过前不得插队。
