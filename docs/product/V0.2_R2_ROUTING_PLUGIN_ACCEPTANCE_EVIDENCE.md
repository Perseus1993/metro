## 已完成能力

1. `algorithm-plugin/v1` 清单固定 `kind=evacuation_routing`，记录插件 ID/版本、`evacuation-routing/v1` API、命令参数数组、Draft 2020-12 参数 schema、能力和元数据。
2. 路由请求包含时刻、起终点、动态关闭边、旅客群组、算法种子、参数和带语义指纹的不可变拓扑；响应包含状态、有序节点/边、有限成本和必填诊断。
3. 应用层拒绝未知版本/能力、无效参数、非有限数、未知节点/边、关闭边、错误邻接、节点环、无路响应夹带路径、缺失诊断和拓扑指纹篡改。
4. 内置确定性 Dijkstra 基线与 `examples/evacuation_routing_plugin/` 外部示例均通过同一合同；示例只导入 Python 标准库，不导入核心包。
5. `metro-station validate-routing-plugin <manifest>` 在独立进程中运行 10 个协议案例，覆盖正常路径、关闭边、无路、起终点相同、不同群组/种子和确定性复跑。
6. 进程宿主不使用 shell，支持逐请求和整次运行超时、启动失败、崩溃退出码、stderr、非法 JSON/路径、显式进程回收和逐请求决策日志。
7. 内置或外部路由端口可通过 `MetroStationModel`/`MesaSimulationExecutor` 构造注入，仅影响疏散意图；真实编译站图和动态设施关闭转换为公共合同，运行时保留决策日志。

## 安全与研究边界

- 插件只能生成到已选战略目的地的全局路径；设施选择、局部运动和实验优化仍是独立边界。
- 进程隔离用于保护批次免受崩溃和超时影响，不是不可信代码安全沙箱；只支持经过审查的本地插件。
- 当前运行桥把设施关闭映射为关闭边；水马/隔离栏/封闭区的几何变化和单向通道尚未重新投影为站图边约束，必须在 R3 配对实验前明确处理或披露。
- 当前构造注入和 CLI 已可验证/运行算法，但设计器算法注册、参数预检和报告展示属于 V02-DEV-009。
- `no_route` 和宿主失败会终止当前算法运行；批次 `partial/failed` 汇总与其他配对结果保全属于 R3。
