# PM-033：复杂行人轨迹修复与独立验收计划

- 状态：实现完成，冻结候选正在做最终全量回归与独立审查
- 范围：仿真真值、展示轨迹、行人 Journey、局部运动、设施服务、列车事件与回放
- 非目标：用视觉插值掩盖仿真错误；在缺少现场标定时宣称安全预测或数字孪生

## 1. 问题定义

旧链路把设施服务窗内的真实坐标覆写为设施起终点线性插值，导致不同乘客长期同点、同速和同步；5 秒一次的过程 tick 又把采样量化伪影混入速度、加速度和转角判断。修复必须先恢复可审计的仿真真值，再改善分层行为与回放，不能依靠针对某一站型、人数、种子或乘客 ID 的补丁。

## 2. P0–P11 实施与验收

| 阶段 | 实施内容 | 自动验收指标 | 独立审查问题 |
|---|---|---|---|
| P0 基线与量具 | 固定种子与同场景对照；建立真值、步行运动、全状态运动、展示保真四门 | 同一输入重复分析报告逐字段一致；四门均能被对应的故意错误触发 | 指标是否真的测到轨迹，而非演示图层 |
| P1 真值/展示隔离 | `simulation_trace.snapshots` 与 `movement_trace` 为科学真值；展示点放入独立字段 | 真值拒绝任何 `visual_only`；同 ID 同时刻多位置为 0；展示源点账本与权威轨迹逐点相等 | 是否仍存在写轨迹阶段的坐标覆写 |
| P2 物理时间与高频采样 | 过程时钟使用真实秒；JuPedSim 内部每 0.2 秒记录运动点；非整 tick 事件不提前 | 步行最大采样间隔 ≤0.2 s；闸机、电梯、需求、警报、列车时刻跨 1/2/4/5 s tick 不提前且结果等价 | 是否用 round/floor 或 tick 数冒充时间 |
| P3 战略 Journey | 行程按进站、换乘、出站、疏散目标表达；疏散图由物理连通分量和实际设施构建 | 1/2/3 层站型均能生成可达 Journey；设施服务完成前不得换层或到达安全区 | 是否有伪决策点、伪完成或穿层 |
| P4 战术路由 | 以 portal 和可步行多边形求同层测地路径，区域目标做稳定分散 | 路段留在可步行区；不同尺度/平移/旋转与多站型性质测试通过；不得切墙、跨障碍 | 是否将站型坐标、中心点或固定 waypoint 写死 |
| P5 队列与反应 | 入口预留、反应时间、容量、严格 FIFO；楼梯单队列不越过队首 | 服务开始顺序与入队顺序一致；同一乘客不可同时拥有两个等待资源；队位不越界、不重叠 | 轨迹中的等待和启动是否像真实排队 |
| P6 JuPedSim 生命周期 | 会话、episode、动态几何与重放置有明确所有权；恢复不得把人跳到目标 | agent ID 稳定；丢失会话无一步瞬移；空会话幽灵可回收；设施关闭种子全部清场 | “恢复”是否只是 teleport 兜底 |
| P7 设施内个体轨迹 | 楼梯、扶梯、电梯、闸机以逐人服务状态产生物理位置；展示只读 | 同设施多人保留时间/空间差；服务起终点连续；闸机时长=距离/速度；电梯可在 tick 剩余时间继续派梯 | 是否又把整段轨迹线性覆写成同一路径 |
| P8 广义成本与重规划 | 路线成本包含测地距离、排队、服务、拥挤与中断；只在决策边界重规划 | 关闭/恢复与拥挤变化能改变可行路线；已在服务中的人完成当前物理过程后再重路由 | 是否是每 tick 抖动，或不可用设施仍被锁死 |
| P9 列车语义 | 到达、开门、下客、上客、容量、满载等待和下一班恢复统一到 Goal 事件 | 满载乘客留在唯一 FIFO 资源；平台等待集与车门队列交集为空；下一班可继续登乘 | 是否出现双重所有权、消失或伪登乘 |
| P10 朝向与播放 | 朝向采用前向运动证据；停止保持最近有效朝向；角度按最短弧插值 | 359°→1° 不绕行；停止不瞬间转向正东；无一帧滞后或倒转一圈 | 仅看播放是否像人在走，而非箭头插值 |
| P11 冻结验收 | 生成 10/50/100 人疏散与复杂运营四套新回放；运行四门及三个独立 agent | 四套报告全部 `pass`；代码/行业审查 PASS；通用性反例审查 PASS；盲轨迹审查 PASS | 结果是否独立于实现知识和特定样本 |

## 3. 四道轨迹门

1. 仿真真值门：有限坐标、时间不回退、同 ID 同时刻唯一位置、持续精确同点对为 0；粗粒度平均速度不得超过 3.5 m/s。
2. 步行运动门：只读 `movement_trace`；最大采样间隔 0.2 s，速度 P99 ≤2.0 m/s，加速度 P99 ≤4.0 m/s²，运动中 ≥150° 转折占比 ≤0.5%。
3. 全状态复合门：把走路、排队、设施服务和等待按权威来源合并；速度 P99 ≤2.0 m/s、任一段 ≤2.2 m/s、加速度 P99 ≤4.0 m/s²，并拒绝高速硬反转与 A→B→A 回跳。
4. 展示保真门：`points` 逐点对应仿真真值；装饰性 `presentation_points` 可以存在，但不得进入科学门禁，也不得修改源点。

任何一门失败，整套场景失败。四门报告必须保留输入边界、阈值、观测值和失败样本，不允许只输出一个布尔值。

## 4. 冻结场景与证据

| 场景 | 固定条件 | 必须输出 |
|---|---|---|
| 疏散 10 人 | 1 s 过程 tick、0.2 s 运动采样、固定种子 | scientific replay、presentation bundle、四门报告、匿名 XY |
| 疏散 50 人 | 同上 | 同上，并核对清场与设施 FIFO |
| 疏散 100 人 | 同上 | 同上，并核对拥挤下无精确同步同点 |
| 复杂运营 | 进/出/换乘同时发生，含设施与列车资源竞争 | 同上，并核对车门/站台资源唯一所有权 |

最终证据必须由当前冻结代码重新生成；历史回放只能作为问题复现材料，不能替代新结果。

## 5. 独立 agent 合同

- 代码/行业 agent：对照 JuPedSim 的 Journey/Stage、动态路径与连续运动建模，以及研究中的活动调度、设施选择和路线成本思想；报告硬失败及源码位置，不接受“测试能过”作为充分理由。
- 通用性 agent：主动改变 tick、几何、站型、设施数量、事件边界、容量和种子，判断实现是在解决合同还是添加兜底；至少两轮，所有反例必须可复现。
- 盲轨迹 agent：只接收匿名 `id,t,x,y`，不接收站型、状态、设施、代码或修复说明；只判断速度连续性、转向、停走、同点、回跳和整体真实感。

## 6. 建模依据与边界

实现采用“战略活动/Journey—战术路径—操作层连续运动”分层：JuPedSim 将行程表示为 Journey/Stage，并在可行走几何上路由；局部避碰沿用 JuPedSim 连续运动后端。复杂设施选择用距离、等待、服务与中断成本表达，但当前阈值仍是工程质量门，不是现场校准结论。
