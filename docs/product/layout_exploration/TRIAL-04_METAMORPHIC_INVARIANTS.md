# PM-028-E4 变形等价与测试敏感性试探包

- 优先级：P1
- 状态：`implemented / 100 pairs passed / 50 of 50 injections detected`
- 依赖：E1稳定案例；可提取规范化拓扑、场景和运行摘要

## 实际结论（2026-07-18）

20个基例×5种变形的100对案例全部满足各自不变量；10个敏感性基例×5种故意破坏全部被检测。集合顺序采用canonical projection定义，装饰语义采用显式 `presentation_only` 元数据，M4在单层或已达6部电梯时明确记录不适用而不伪造变化。

## 要回答的问题

很多问题没有单一“正确截图”或精确清场时间，但可以判断某种输入变换后哪些事实必须保持、哪些事实允许变化。E4用成对变形验证生成器、编译器、仿真和展示不会把文件顺序、绝对坐标或装饰资产误当成业务语义。

## 基例选择

选择20个 `VALID` 基例：

- 四种平面各5例；
- 一、二、三层均覆盖；
- 0、1、3、6部电梯均覆盖；
- 单簇、双簇和已决定支持的分段跨层均覆盖；
- 稀疏、标准、密集资产均覆盖；
- 双向闸机和进出分离均覆盖。

每个基例先重复生成和运行两次，确认自身确定性，再执行五种变形。

## 五种变形与100对案例

### M1：集合顺序置换

固定seed打乱 `levels/elements/queues/connections/ports` 的序列顺序，不改变ID和引用。

必须保持：

- 校验诊断集合；
- 规范化图节点/边集合；
- 运行设施到物理实体的映射集合；
- 四类旅程可达性；
- 人员守恒和终态计数。

产品决定是集合顺序不属于业务语义。实现通过显式canonical projection比较稳定集合和canonical fingerprint，不要求原始JSON字节或顺序敏感fingerprint相等。

### M2：镜像 + 镜像需求

水平镜像足迹、元素、队列、服务点、方向角和轨迹起终点，并交换对应入口权重。

必须保持：

- 楼层、设施种类、连接和运行绑定数量；
- 规范化后旅程完成数、事件种类和人员核算；
- 浏览器实体与关系完整性。

允许变化：绝对坐标、实体绘制顺序和原始几何指纹。若运动后端确定且只依赖相对几何，可额外审计逆镜像后的轨迹一致性，但首版不作为发布门禁。

### M3：删除非拓扑装饰

删除被明确标记为 `presentation_only/non_blocking` 的装饰元素及资产绑定。

必须保持：

- 拓扑节点/边和四类旅程可达性；
- 运行设施集合与绑定；
- 人员守恒和终态授权。

不得把shop、equipment或obstacle仅凭kind自动视为装饰；如果它参与可行域或阻挡，删除会改变运动路径，不属于此变形。实现前必须有显式metadata合同。

### M4：增加冗余电梯

在不重叠且连接相同楼层的位置增加一部物理电梯，并重新派生端口、连接、队列、运行设施和资产绑定。

必须保持或满足：

- 原有拓扑路径仍存在，可达节点集合不减少；
- 原有设施和scene entity ID保持稳定；
- 物理电梯实体数增加1；
- 新增运行设施数量与编译结果一致，全部只绑定到新电梯实体；
- 未关联的闸机、站台和列车运行绑定不变化。

不要求清场时间单调改善，因为设施选择和排队策略可能改变。

### M5：全局平移

在画布和所有楼层足迹允许范围内，将足迹、元素、队列、服务点、端口位置和需求起终点整体平移固定向量。

必须保持：

- 拓扑、运行绑定、旅程结果和聚合指标；
- 逆平移后的轨迹点序列或轨迹语义摘要；
- 浏览器无裁切且scene coordinate system正确包围所有实体。

绝对坐标和几何指纹允许变化；规范化拓扑与逆变换轨迹应相等。

总计：`20基例 × 5变形 = 100对`。

## 不变量分层

| 层 | 可比较投影 | 不应直接比较 |
|---|---|---|
| 设计 | ID集合、kind、level、连接端点、方向 | 原始JSON字节、生成时间 |
| 拓扑 | 规范化节点/边、可达性、服务方向 | 内部对象地址、遍历顺序 |
| 回放 | entity/relation/runtime/asset binding集合 | Canvas绘制顺序 |
| 仿真 | 人员核算、终态计数、事件事实、规范化轨迹 | wall time、未规范化绝对坐标 |
| 展示 | 实体数、楼层数、诊断、像素包围盒 | 全图像素逐点相等 |

## 测试敏感性：故意注入错误

变形测试本身也可能“永远通过”。从10个基例各注入以下5类错误，形成50个敏感性案例：

1. 删除一条旅程关键边；
2. 将一个runtime binding指向错误电梯；
3. 删除一个asset binding；
4. 修改一个队列owner；
5. 镜像几何但不镜像服务点或需求入口权重。

要求相应门禁至少有一个失败，且失败阶段符合预期。敏感性得分为 `被检测的注入错误数 / 总注入错误数`，P0错误目标为100%；不能只报告普通测试通过率。

## 执行方法

1. 为每种变形定义独立、纯函数式的domain操作，不在浏览器或测试断言里偷偷修改数据。
2. 生成baseline与transformed两个完整产物链。
3. 通过明确的规范化投影比较，不直接比较不稳定字段。
4. 输出每条不变量的 `same/changed/not_applicable` 和差异摘要。
5. 若失败，先最小化基例，再最小化变形参数。

## 验收标准

- 100对案例全部满足各自声明的不变量；
- 50个故意错误的P0敏感性为100%；
- 不用像素逐点相等或wall time作为等价依据；
- 顺序是否属于语义、装饰元素如何标记形成正式合同决定；
- 相同案例和变形seed复跑产生相同差异摘要；
- 任何被允许变化的字段都有解释，不能用通配忽略整个对象。

## 退出条件

五种变形均有机器可读不变量清单、规范化投影和失败差异；顺序语义与装饰标记两个审计决定均已关闭并进入持续回归。
